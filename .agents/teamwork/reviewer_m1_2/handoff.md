## 3. Caveats & Adversarial Findings

1. **Adversarial Finding — TikTok HTTP 200 with Error Body (Minor / Informational)**:
   - *Observation*: If TikTok API Init returns HTTP status 200 with an error JSON body (e.g. `{"error": {"code": "access_token_invalid", "message": "..."}}`), `upload_url` is `None`. The current code returns `{"status": "success", "publish_id": None, "upload_url": None}` instead of `{"status": "error"}`.
   - *Impact*: Low in current staging, because invalid tokens usually return HTTP 401/403 which raises `urllib.error.HTTPError` (already caught cleanly).
   - *Recommendation for future hardening*: Add `if resp_data.get("error", {}).get("code") not in (None, "ok", 0): return {"status": "error", "error": resp_data["error"]}`.
2. **Video Chunking for Files > 64MB (Assumption Validation)**:
   - *Observation*: TikTok single-chunk PUT uploads are bounded at 64MB.
   - *Impact*: In the current context of short preaching clips (30-60 seconds 1080x1920), clip sizes range from 5MB to 40MB, staying well within single-chunk limits.
3. **External Network Live Credentials**:
   - Real live upload to TikTok servers is tested via unit test mocks and local payload generation, since no live developer production secrets are supplied in the test VM.
